# 미국판 무칩·100% 후보 v2 — 상태 전달 경로 추가

**실제 기기의 부팅·무칩 인쇄·복구는 아직 검증하지 않은 실험 후보입니다.**
v1은 사용자 기기에서 실패했습니다. v2의 ARM 검증 통과가 실기 성공을 보장하지 않습니다.

[v2 EFU 다운로드](https://raw.githubusercontent.com/ZanghyunCho/TX720/main/firmware/FWC365TL_US_chipless_candidate_v2_EXPERIMENTAL.efu)

대상은 제공받은 미국판 `FWC365TL.efu` (`21.21.AW03G6.FY10`, `AW*FY10`)입니다.
스캐너 유닛 닫힘 패치와 v1의 합성 칩 읽기를 포함합니다.
지역·버전 메타데이터, 언어 리소스, 두 번째 IPL 및 원래 업데이트 보조 코드를 유지합니다.
정상 인쇄에는 실제 잉크 공급이 필요합니다. 잔량 100%는 실제 잉크 양을 측정하지 않습니다.
빈 카트리지 상태로 인쇄나 헤드 청소를 하지 마세요.

## v1 실패에서 확인한 점

사용자 보고는 카트리지가 없을 때 “바르게 장착될 때까지 아래로 누르십시오”,
빈 카트리지를 넣으면 “다음 잉크 카트리지를 교체해야 합니다”였습니다.
원본 더미 칩 승인 함수만 실행한 v1 검증은 이 실기 오류를 재현하지 못했습니다.

장착 불량 문구에 해당하는 미국판 리소스는 인덱스 206이며, 원본 화면 처리부
`0x1ddbcc`는 이벤트 `0x362`에서 이를 선택합니다.
상태 전달 경로에는 칩 읽기 외에 별도의 6채널 장착 상태와 잉크 종료 상태가 있습니다.
원본 상태 수신부 `0x41ad1778`와 오류 판정 함수 `0x41ad4384`를 추가로 추적했습니다.

v2는 이 별도 경로를 대상으로 합니다. 이것이 실기 실패의 유일한 원인이라는 주장은 하지 않습니다.

## v2 변경

ROM의 상태 송신 API `0x11cb5c`를 감싸 다음 입력만 바꿉니다.

| 메시지 ID / 길이 | 전달할 데이터 |
| --- | --- |
| `0x15` / 6바이트 | 6색 잔량 모두 100 |
| `0x16` / 6바이트 | 6색 종료 상태 모두 1 (정상 상태) |
| `0x211` ~ `0x216` / 1바이트 | 채널별 장착 상태 1 (정상 상태) |

그 밖의 ID와 예상 길이가 다른 메시지는 그대로 원래 API로 보냅니다.
호출자 버퍼는 수정하지 않고 스택에 만든 복사본을 원래 API가 큐 메시지로 복사하게 합니다.
메시지를 버리거나 오류 화면 함수를 무조건 성공으로 바꾸는 수정은 아닙니다.

6색 잔량 캐시 getter `0x1fd8a8`도 100을 반환하게 바꿉니다.
상태 전달 코드 124바이트는 v1에서 대체한 읽기 함수의 사용하지 않는 뒷부분
`0x489c0` ~ `0x48a3b`에 둡니다. 다음 원본 함수 `0x48a48` 앞에서 끝납니다.
원본 ROM/CROM 블록의 정렬된 직접 분기·절대 포인터 검사에서 이 영역으로 들어오는
외부 참조는 없었습니다. 동적 실행 전체를 증명하는 검사는 아닙니다.
압축 RAM 코드의 재작성이나 새 메모리 영역은 사용하지 않습니다.

## 실행 검증

실제 패키지에서 코드를 다시 읽어 Unicorn 2.1.4로 실행했습니다.

- 상태 API 입력 4,096건: 256개 값, 읽기 전용/일반 버퍼, 관련 ID 8종.
- 다른 ID·다른 길이 108건: 원본 데이터가 그대로 큐에 복사되는지 확인.
- 잔량 getter 1,536건: 캐시 값 0~255 × 6색 모두 반환 100.
- 원본 상태 저장·오류 판정 코드의 수정 전/후 비교 30건:
  6색 각각 장착 상태 2·3·4·5와 종료 상태 3에서 수정 전 오류가 발생하고,
  수정 메시지를 전달하면 해당 오류가 해제됐습니다.
- 잉크 외 메시지 `0x0c=1`은 원본 오류 비트 `0x8`을 계속 발생시켰습니다.
- 호출자 데이터·양쪽 경계·스택·보존 레지스터 및 원래 API의 메시지 헤더·복사를 검사했습니다.
- v1의 합성 칩 읽기·승인·메시지 생성 검사도 v2 패키지에 다시 실행했습니다.

실제 RTOS 큐·태스크 식별 서비스, 마지막 오류 플래그 저장/알림은 모의 구현입니다.
상태 API 래퍼, 원래 메시지 복사, 원래 상태 저장 및 오류 결정 분기는 ARM 코드로 실행합니다.
이 검사는 실기 부팅이나 전체 인쇄 상태 머신 검증이 아닙니다.

## 원본에서 재현

```sh
python3 tools/patch_us_chipless_candidate.py FWC365TL.efu output/US_v2.efu --manifest output/patch.json --revision 2
python3 tools/validate_us_chipless_v2.py --analysis-root /path/to/firmware-analysis output/US_v2.efu --output output/validation.json
python3 tools/verify_packages.py
```

정확한 원본 SHA-256만 허용하며, 기존 출력 파일을 덮어쓰지 않습니다.
원본·CROM 추출 데이터는 저장소에 포함하지 않습니다. v1 다운로드와 실기 실패 기록은 그대로 보존합니다.
