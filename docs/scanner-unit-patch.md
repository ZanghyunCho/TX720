# 스캐너 유닛 닫힘 패치 분석

## 입력과 범위

제공받은 일본판 `FWC365TL_JP.efu`와 미국/영어판 `FWC365TL.efu`를 각각 분석했습니다.
원본 SHA-256은 `reports/jp-patch.json`, `reports/us-patch.json`과 재현 도구에 기록됩니다.
패치 파일은 `firmware/`에 있으며, 실기 검증은 수행하지 않았습니다.

두 파일 모두 ZIP 안의 RCX에 IPL6 이미지 두 개를 포함합니다. 첫 IPL은
8,335,360 바이트, 두 번째 IPL은 7,811,072 바이트입니다. RCX 메타데이터는 327바이트입니다.
이름이 비슷해도 일본판 `AJ06I7`과 미국판 `AW03G6`의 코드 주소는 다릅니다.

## 추적한 센서 경로

펌웨어 자체의 구형 CROM 해제 루틴을 Unicorn 2.1.4에서 실행해 코드·데이터를 추출했습니다.
Capstone 5.0.6으로 ROM 코드와 추출된 RAM 코드를 분석했습니다. 기기 또는 업데이트 도구와
통신하지 않았습니다. 아래 주소는 **실행 주소**입니다.

| 항목 | 일본판 AJ06I7 | 미국판 AW03G6 |
| --- | --- | --- |
| 센서 점검 루프 | `0x41b1829c` | `0x00180ef8` |
| 점검용 닫힘 getter | `0x41b59f88` | `0x001c6634` |
| 기존 우회 플래그를 확인하는 ROM getter | `0x000ea808` | `0x00128e10` |
| 플래그 검사 없이 읽는 raw getter | `0x000ea834` | `0x00128e3c` |
| 센서 입력 | `0xf8016024` bit 6 | `0xf8016024` bit 6 |
| 기존 우회 플래그 주소 | `0x400d2d04` | `0x400d2fd8` |
| 일반 동작 getter | `0x41aedd04` | `0x41ad5b00` |
| 일반 동작 검사 경로 | `0x41a44458` | `0x41a40b8c` |

점검용 getter는 ROM getter 반환값 `raw`를 `1 - raw`로 바꿉니다.
점검 루프는 이 결과가 1이면 `Close!`, 아니면 `Open!`을 표시합니다.
따라서 원래 입력 비트가 0이면 닫힘, 1이면 열림입니다.
일반 동작 검사 경로도 동일한 ROM getter를 호출합니다.

플래그 검사 없는 별도 경로도 발견해 두 getter를 함께 수정했습니다.
함수 호출과 스택 구조, 조건 플래그를 변경하는 대신 최종 반환값 산출 명령어만 바꿉니다.
압축 블록을 수정하거나 재압축할 필요가 없습니다.

## 패치 위치

아래 파일 오프셋은 **첫 IPL 이미지 내부** 기준입니다. RCX 파일 오프셋은 여기에
`0x147`을 더한 값이며, 실행 주소는 해당 파일 오프셋에 `0xd000`을 더한 값입니다.

| 원본 | IPL 파일 오프셋 | 실행 주소 |
| --- | --- | --- |
| JP | `0x000dd824` | `0x000ea824` |
| JP | `0x000dd840` | `0x000ea840` |
| US | `0x0011be2c` | `0x00128e2c` |
| US | `0x0011be48` | `0x00128e48` |

각 지점에서 ARM little-endian 명령어 `a0 0f a0 e1` (`lsr r0, r0, #31`)을
`00 00 a0 e3` (`mov r0, #0`)으로 바꿉니다. 두 명령어 모두 조건 플래그를 갱신하지 않습니다.
원본 이미지와 명령어가 정확히 일치하지 않으면 재현 도구는 패치를 거부합니다.

## 무결성 필드

이 구형 IPL6 헤더는 16바이트 레코드 3개(`0x30`)를 사용합니다.

- `0x12`: `image[0x1000:0x3000]`의 바이트 합계 하위 16비트.
- `0x22`: `image[0x3000:]`의 바이트 합계 하위 16비트.
- `0x40:0x54`: `SHA1(payload || SHA1(image[:0x0e]))`.

SHA-1 구성의 단서는 James Wah의 공개 도구
[rcx_correct](https://github.com/abrasive/epson-reversing/blob/2ed0a54a4ba98c9a860bf2e0efbfc4d53c0e4a16/rcx_correct)에서
얻었습니다. 그 도구가 가정하는 새 헤더 형식과 이 펌웨어의 레코드 길이가 달라,
그대로 실행하지 않고 구형 형식에 맞춰 구현했습니다.
**원본 4개 IPL 이미지 모두** 기존 합계와 SHA-1 값을 정확히 재현했습니다.
이는 제조사 서명 검증이나 실제 업데이트 수락을 확인한 것은 아닙니다.

| 원본 | 첫 IPL 기존 본문 합계 | 패치 후 합계 |
| --- | --- | --- |
| JP | `0x748f` | `0x7335` |
| US | `0x84d2` | `0x8378` |

두 번째 이미지, 원래 버전/대상 메타데이터, 언어 리소스는 보존합니다.
패치된 첫 이미지의 차이는 두 명령어와 관련 합계 및 SHA-1 필드로 한정됩니다.

## 검증 결과와 한계

각 버전의 원본과 수정본에 대해 입력 바이트 0–255 전체와 기존 우회 플래그
0, 1, 2, 255를 넣어 실제 ARM 명령어를 실행했습니다. MMIO는 메모리로 모사했습니다.
원본은 입력에 따라 열림/닫힘이 바뀌고, 수정본의 확인된 경로는 항상 닫힘 값을 반환했습니다.
일반 동작 getter·중계·검사 함수와 점검용 getter, raw getter 소비자까지 검사했습니다.
스택과 callee-saved 레지스터도 보존되었습니다.

각 버전 15,360회, 합계 30,720회 함수 호출 검증이 통과했습니다.
별도 Photo Tray와 DUP 입력의 getter는 기존 입력에 따른 반환값을 유지했습니다.
해당 결과는 `reports/jp-arm-validation.json`, `reports/us-arm-validation.json`에 있습니다.

전체 인쇄 작업이나 모든 펌웨어 상태를 에뮬레이션한 것은 아닙니다.
실제 프린터의 업데이트 수락, 부팅, 인쇄, 스캔, 복구 및 지역 간 펌웨어 전환은 미검증입니다.
같은 버전의 재기록 허용 여부도 확인하지 않았습니다. 실제로 검증된 복구 경로가 없습니다.
패치 후 유닛을 열어도 닫힘으로 읽도록 의도했으므로 내부 작업은 전원을 분리하고 해야 합니다.
