# 무칩·잔량 100% 요청 분석 상태

목표는 미국판과 일본판 모두에서 칩 없이 인쇄하고 여섯 색 잔량을 항상 100%로 보고하는 것입니다.
기존 EFU는 스캐너 유닛 닫힘 패치만 포함합니다. 후속 작업에서 미국판 전용
[더미 칩 응답 후보 v1](us-chipless-candidate-v1.md)을 별도로 만들었습니다.
해당 후보는 원본 승인·100% 생성 함수의 ARM 검증을 통과했지만 실기 부팅·인쇄는 미검증입니다.
아래는 후보 제작 전 잔량 단독 변경의 한계를 확인한 선행 분석입니다.

## 원본 ARM 코드 실행으로 확인한 사실

잔량 캐시만 여섯 색 모두 100으로 설정해도 다음 독립 상태가 오류를 발생시킵니다.

- 채널별 칩 상태 2, 3, 4, 5
- 채널별 별도 잉크 종료 상태 `0x85`

각 버전에서 정상 1건과 오류 30건을 실행했습니다. 정상 상태에서는 오류 이벤트가 해제되고,
30개 오류 입력에서는 잔량 getter가 모두 100을 반환해도 이벤트 `0x88`의 오류 플래그가 1입니다.
또한 채널 6개 × 상태 코드 256개, 총 1,536건의 원본 변환 함수를 실행했습니다.
이 결과는 표시값 고정만으로 칩 없는 인쇄가 가능하다는 주장에 대한 반례입니다.

| 역할 | 미국판 런타임 주소 | 일본판 런타임 주소 |
| --- | --- | --- |
| 잔량 캐시 getter | `0x001fd8a8` | `0x0016030c` |
| 잔량 캐시 | `0x400d5dbf` | `0x400d5aeb` |
| 칩 상태 변환 | `0x41abfa84` | `0x41acc138` |
| 칩/종료 오류 집계 | `0x41ac0afc` | `0x41acd1b0` |
| 내부 상태 루트 | `0x4017ad54` | `0x40158474` |
| 상태 패킷 처리부 | `0x41ac2a04` | `0x41acf0b8` |

상태 루트의 `+0x28`에는 6개 칩 상태, `+0x40`에는 별도 6개 상태가 있습니다.
속성 `0x42A`(칩 상태), `0x42C`(잔량), `0x42D`(종료 관련 상태)는 별도입니다.
서비스 화면의 CSIC 판정 또한 잔량 getter와 다릅니다.

미국판에서는 `0x41a49620`이 6채널 × 3바이트 정보를 큐 메시지 `0x32`로 포장하고,
상태 디스패처가 이를 `0x41ac2a04`로 전달하는 경로까지 추적했습니다.
이 메시지의 작성자 중 하나는 `0x41a40c84`입니다.
이는 소프트웨어 상태 전달 경로이며, 물리 칩 통신 성공이나 인쇄 가능성을 검증한 결과는 아닙니다.

미국판 `0x41a40c84` 내부에는 `0x41a35e4c`가 1이면 채널 잔량을 100,
상태를 `0x80`으로 만드는 기존 분기도 있습니다. 해당 판정은 여섯 채널 모두에서
`0x41a35de0`가 1이어야 합니다. 후자는 `0x41a3589c`로 읽은 필드 8, 9, 7이
각각 5, 4, 1인지 확인합니다. 이 판정만 강제하면 무칩으로 부팅·인쇄한다는 근거는
아직 없으며, 칩 인증 또는 다른 차단 경로를 함께 해결했다고 해석할 수 없습니다.

## 검증 범위와 재현

검증 도구는 원본 코드와 모의 RAM을 Unicorn으로 실행하며 펌웨어를 수정하지 않습니다.
집계 함수의 마지막 이벤트 수신부는 기록용 stub입니다. 서비스 화면 판정용 속성 getter도
원본 상태 바이트를 반환하는 명시적 stub입니다. 물리 버스·프린터 부팅·인쇄는 모사하지 않습니다.

```sh
python3 tools/probe_ink_paths.py --analysis-root /path/to/firmware-analysis --output-dir reports
```

필요 입력은 원본에서 추출한 `part1.ipl` 및 `crom-extracted/{40000000,41a0d000,43e51000}.bin`입니다.
일본판은 분석 루트, 미국판은 그 아래 `us/`에 둡니다. Unicorn 2.1.4가 필요합니다.
분석 환경에서는 `python-libs/`에 설치했습니다. 원본 파일과 추출 데이터는 저장소에 포함하지 않습니다.

결과: [일본판](../reports/jp-ink-path-probes.json), [미국판](../reports/us-ink-path-probes.json).
남은 과제는 칩 통신 실패 시 초기화·인쇄 허용 경로를 확인하고, 두 원본의 수정 및 검증을 연결하는 것입니다.
